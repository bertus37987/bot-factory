# Pre-V2 Harness Code Audit

> Archived Antigravity `harness-auditor` report (swarm board entry 72). Line numbers refer to the pre-V2 code, not the current checkout. The proposed fixes are historical recommendations; see the V2 synthesis for what landed.

### 1. Tool-execution loops & doom-loop vulnerability (`nativeHttpRuntime.ts`, `agentTools.ts`, `engine.ts`)
- **No doom-loop circuit breaker** (`nativeHttpRuntime.ts:26, 529-575, 624-860, 915-1055, 1107-1327`): Loops up to `DEFAULT_MAX_TOOL_STEPS = 12` with zero tracking of repeated identical `(name, canonicalArgs)` calls, repeated `parseError`s (`:544-546, 837-844, 1301-1304`), or consecutive all-error steps.
  - *Wave 2 fix*: Track `(name + sortedJsonArgs)` call counts and consecutive error-only steps inside each provider loop; on >=2-3 identical calls or >=3 consecutive error steps, inject a deterministic error/stop nudge and exit tool loop.
- **Final-step `tools` omission breaks Anthropic / strict gateways** (`nativeHttpRuntime.ts:625, 641, 916, 933, 1108, 1126`): When `step === maxToolSteps`, `canOfferTools` turns `false` and `body.tools` is omitted while `messages` still ends with `tool_use` + `tool_result` / `role:"tool"` (`:818-854, 1310-1320`), causing Anthropic API HTTP 400 (`tools` required when tool blocks exist).
  - *Wave 2 fix*: Keep `tools` present on the final step with `tool_choice: "none"` (OpenAI/Anthropic) / `toolConfig.functionCallingConfig: { mode: "NONE" }` (Gemini) or stop before a final tool-less step with a synthetic user wrap-up turn.
- **Unbounded tool outputs & intra-turn bloat** (`nativeHttpRuntime.ts:549-550`; `agentTools.ts:622-653, 726, 736-746, 851-854`): `executeToolCalls` pushes full `stringifyToolOutput(raw)` into `messages` and DB `TimelineItem`s (`engine.ts:2077-2096`) with zero truncation. `bf_team_status` (`agentTools.ts:622-653`) dumps all projects/tasks/goals/10 verification reports w/ 4KB summaries; `bf_repo_diff` dumps full diffs; `bf_task_create_batch` echoes all `specMd`s.
  - *Wave 2 fix*: Cap tool outputs for LLM context (e.g. 12KB head+tail truncation) in `executeToolCalls`, slim `bf_team_status`/`bf_task_create_batch` payloads, and age/mask tool outputs older than 2 steps during long loops.
- **CRITICAL — History wipe after 12 tool calls & KV cache bust** (`engine.ts:1980-1994, 2077-2096`; `database.ts:1308-1312`): `executeToolCalls` emits 2 `tool_call` events per call (`in_progress` at `:535`, `completed/failed` at `:557`); `engine.ts:2078, 2095` inserts 2 separate `messages` rows for every non-`chat:meta` agent. `listActiveSessionMessages(session.id, 24)` applies `LIMIT 24` in SQL *before* JS filters out `tool_call`/`thought`/`plan` (`engine.ts:1982-1986`). A single 12-call turn produces 24 `tool_call` rows, wiping prior `user`/`assistant` history to `[]` on the next turn. Also `LIMIT 24` shifts `history[0]` every turn >24, busting KV prefix cache.
  - *Wave 2 fix*: Filter `kind IN ('message','status')` in SQL in `listActiveSessionMessages`, upsert `tool_call` rows by `toolCallId` instead of double-inserting, and pin/anchor history truncation only on compaction boundaries.
- **CRITICAL — Gemini & Anthropic drop Compaction summaries** (`nativeHttpRuntime.ts:880, 1074` vs `engine.ts:1985-1988`; `database.ts:1087`): `Compaction Gen #N` is stored as `role: "system"`, and both `callGoogleGemini` (`:880`) and `callAnthropic` (`:1074`) filter out `role === "system"` from `history`, causing total amnesia after compaction.
  - *Wave 2 fix*: Map `Compaction Gen #N` history entries to a `user`/`assistant` context pair (or `[Session Compaction Summary]` user message) in Gemini/Anthropic adapters (and avoid mid-array `system` messages on strict OpenAI gateways).
- **Prompt cache / HTTP timeouts / thinking block edge cases** (`nativeHttpRuntime.ts:645, 729, 937, 970, 1112-1128, 1130, 1213, 1280-1285`): No `cache_control: { type: "ephemeral" }` breakpoints in `callAnthropic`; `:1281-1285` can emit `{ type: "thinking", thinking: "" }` without required `signature`; `fetch()` has no per-request timeout (can wedge `work` lane forever); multi-step text concatenates without `\n\n`.

### 2. Continuous DAG autonomy & retry loops (`autonomyLoop.ts`, `verifier.ts`, `engine.ts`)
- **Verifier failure details truncated/dropped on retry** (`verifier.ts:227-235, 463-465`; `autonomyLoop.ts:69-77, 276-280`):
  - `verifier.ts:463-465` truncates `c.detail` to **200 chars** (cutting off the end of the 800-char tail from `:228` where actual compiler/test errors live).
  - `autonomyLoop.ts:276-279` ignores `report.checks` (full 800-char details) and ignores `report.summary` whenever `report.findings.length > 0`.
  - `autonomyLoop.ts:75-76` (`appendRetryFeedback`) slices `combined.slice(combined.length - MAX_SPEC_RETRY_CHARS)` from the **front**, deleting the start of original `specMd` on large specs/retries.
  - *Wave 2 fix*: Keep full failed `report.checks` (up to ~800 chars each) + `findings` + `summary` excerpt in a structured retry feedback block; preserve the original `specMd` head intact and cap/rotate only old retry attempts.
- **Verifier branch-commit blind spot** (`verifier.ts:723-729`): `computeBranchCommitsDiff` only runs if `computeWorkspaceGitDiff` finds `filesChanged === 0` (`:724`). If an author bot committed changes and left 1 uncommitted file (e.g. `.bf-task-*.md` or doc note), the verifier only sees that 1 file and misses the entire committed branch diff.
  - *Wave 2 fix*: Always include/merge `computeBranchCommitsDiff` when `worktreePath !== project.repoPath`, even when uncommitted changes exist.
- **In-memory `AutonomyLoop` state lost on restart** (`autonomyLoop.ts:80-83, 259`): `goals`, `activeGoalByProject`, `autonomousTaskIds`, `pendingCheckKeys` are purely in-RAM `Map`/`Set`s — daemon restart orphans active goals and turns `isAutonomousTask(taskId)` to `false`, breaking DAG progression.
  - *Wave 2 fix*: Persist `team_goals` + `tasks.is_autonomous` (or `goal_id`) in SQLite and rehydrate `AutonomyLoop` on startup.
- **Starvation & DAG freeze edge cases**:
  - `onPeerTaskFailed` (`autonomyLoop.ts:249-255`) never calls `releaseAuthorAgentIfIdleable` on retry exhaustion, leaving the peer in `"error"` holding a `maxConcurrentBotsPerProject` slot (`engine.ts:1096`).
  - `onVerificationCompleted` (`fail` exhausted at `:286`), `executeTaskMerge` (`engine.ts:3409`), and `bf_task_update` (`agentTools.ts:856-890`) release peers or mark tasks `merged`/`ready` without calling `dispatchUnblockedTasks`.
  - One failed task sets `goal.status = "blocked"` (`autonomyLoop.ts:252, 288`), immediately freezing `dispatchUnblockedTasks` (`:378: goal.status !== "active"`) for *all* independent parallel DAG branches.
  - `requeueTaskForRetry` (`:337-373`) swallows `dispatchTask` errors and assigns a fresh peer with an empty worktree if the original peer isn't `idle`, losing partial work; `pm.goal.turn` creating 0 tasks leaves `goal` stuck `"active"` forever (`engine.ts:617`, `autonomyLoop.ts:454`).
  - `executeTaskVerification` (`engine.ts:2576-2594`) sets `status="blocked"` + emits an `"action"` notice before `onVerificationCompleted` immediately retries to `"ready"`.

### 3. Subagent delegation & worktree patch merging (`subagentManager.ts`, `worktrees.ts`, `mcpBridge.ts`)
- **Raw string output vs typed envelope** (`subagentManager.ts:95-104, 361-377, 379-441`): `getStatus` and `waitForSubagent` return `{ subagent, timedOut?, latestOutput: string | null }`. When `turn.ok === false`, `latestOutput` is `null` or stale from an earlier turn, with no `error`, `status`, `changedFiles`, or `diffStat`, and no `bf_subagent_diff` tool for parent review prior to `applySubagentPatch`.
  - *Wave 2 fix*: Return a typed `SubagentResultEnvelope` (`status`, `summary`, `error`, `changedFiles`, `diffStat`, `timedOut`) and expose read-only `bf_subagent_diff`.
- **Missing patch containment & safety guards** (`subagentManager.ts:509-624`; `worktrees.ts:742-858`):
  - `extractAndApplySubagentPatch` (`:783-803`) filters only `isSensitiveRepoRelPath`. It does **not** reject `mode 120000` (symlinks pointing outside `parentWorktreePath`), validate `isPathStrictlyWithinRoot(parentWorktreePath, path)` on diff targets/renames, enforce optional `allowedPaths` scope on `spawnSubagent`, or take a pre-apply parent checkpoint (`captureCheckpoint`) before `git apply`.
  - `worktrees.ts:758`: If `subagentBaseRefName` is missing, `diffBase` falls back to `"HEAD"`, silently dropping committed changes on the child branch (should fall back to `merge-base` or fail closed).
- **CRITICAL — `mcpBridge.ts:414-418` cuts off default `bf_subagent_wait` at 15s**: `DAEMON_FETCH_TIMEOUT_MS = 15_000`, and `requestedWaitMs` evaluates to `0` when `args.timeoutMs` is omitted — even though `subagentManager.ts:42` defaults `waitForSubagent` to `60_000`ms!
  - *Wave 2 fix*: Default `requestedWaitMs` to `60_000` when `name === "bf_subagent_wait"` and `args.timeoutMs` is omitted.
- **Orphan worktree leaks & cleanup desync** (`subagentManager.ts:142-148, 547-590`; `engine.ts:1747, 1869`): `cleanupSubagentsForParent` is never called when `executePeerTask` completes/fails, leaving orphan `bf/sub-*` worktrees and sidekicks counting against `maxSubagentsPerBot (3)` across tasks. In `applySubagentPatch` (`:547-590`), an unhandled `EBUSY` error in `cleanupSubagentWorktree` runs *after* patching `parentWorktreePath` and aborts the DB update (`status: "stopped"`), unlike `cleanupSingleSubagent` (`:659-671`).

### 4. Memory hygiene & compaction (`memoryEngine.ts`, `engine.ts`, `database.ts`, `index.ts`)
- **Compaction trigger measures billed tokens, not context window** (`engine.ts:2120, 2239-2240`; `database.ts:1103-1120`): `addSessionTokenUsage` sums `token_in` across every tool step inside a turn (a 6-step turn on a 10k context bills ~75k and prematurely compacts), while sessions without `usage` events never compact. No pre-turn/mid-turn check exists.
  - *Wave 2 fix*: Track `lastStepPromptTokens` (plus char/4 fallback on active messages) separately from cumulative billed tokens, and check pre-turn.
- **Multi-gen compaction wipes prior summaries** (`engine.ts:2241-2264`; `database.ts:1069-1094`): `listActiveSessionMessages(session.id, 40)` suffers the same `tool_call` row truncation; `.filter(m => m.kind === "message")` drops `Compaction Gen #(N-1)` (`kind: "status"`) while `compactSessionInPlace` deactivates it (`active = 0`). Also `engine.ts:2252-2254` duplicates `updateSessionSystemPrompt`, and `session.compacted` isn't emitted to `chat:meta` for `Meta-Orchestrator`.
- **L1 budget enforcement gaps** (`memoryEngine.ts:173-193, 201-262, 625-655`): `writeL1File` checks `maxChars`, but `readL1File` (`:173-183`) and `buildFrozenSystemPrompt` (`:206-210`) do **not** truncate/clamp on read (and `:176` caps gauge display at `100%`), allowing disk/ACP edits to blow up `systemPrompt`; `writeL1File` (`:191`) isn't atomic; `rememberFact`/`runDreamBatch` don't bound individual `factText` lengths or total `tier3Volatile` size.
- **Dreaming failure recovery & concurrency races** (`memoryEngine.ts:315-355, 382-479, 588-623`; `index.ts:166`; `database.ts:1538-1582`):
  - `runDreamBatch` catch (`:455`) silently returns `0` with no retry/backoff; `dream_status = 'pending'` docs stay stuck (and aren't scanned on daemon startup).
  - `index.ts:166` truncates `chunksBlock` at 16,000 chars while `memoryEngine.ts:446` marks *all* `docIds` (`maxBatchDocs=8`) as `'done'`, silently losing docs beyond 16KB.
  - `updates` (`memoryEngine.ts:408`; `database.ts:1538-1575`) does not validate `u.oldId` existence (unlike `extends`/`derives`), creating dangling edges; `ingestDocument({ instant: true })` (`:316-319, 353-355`) returns early if another dream is in flight before its own doc finishes.
  - `prefetchCache` (`memoryEngine.ts:133, 588-623`; `engine.ts:2002`) is keyed only by `namespace` (parallel bots overwrite each other) and isn't cleared in the `catch` (`:620`), leaking stale prior-turn recall on error.

### 5. Multi-runtime resilience (`acpSubprocessRuntime.ts`, `cliStreamRuntime.ts`, `engine.ts`)
- **CRITICAL — `cliStreamRuntime.ts` breaks Codex multi-turn `resume` after Turn 1** (`cliStreamRuntime.ts:255-260, 622, 645`; `engine.ts:1898-1906`): Codex spawns a per-turn `codex exec` process (`state.proc = proc` at `:622`) that exits after Turn 1, leaving `state.proc` pointing to the exited process (`exitCode === 0`). On Turn 2, `engine.ts:1901` calls `cliRuntime.isSessionAlive()`, which returns **`false`** (`:259`), so `engine.ts:1903-1905` deletes the handle and calls `startSession`, wiping `externalSessionId` (`:319`) and killing `codex exec resume`.
  - *Wave 2 fix*: Null `state.proc` when Codex `proc.exited` settles cleanly (or check `adapter === "codex" && !state.stopping && !state.closed` in `isSessionAlive`).
- **Process cleanup, Windows `.cmd` quoting & token exposure** (`acpSubprocessRuntime.ts:432-440, 914-985`; `cliStreamRuntime.ts:113-122, 446, 1108-1173`; `engine.ts:1917-1940`):
  - `terminateProcessTree` never awaits `proc.exited` and on POSIX sends only `SIGTERM` (no `SIGKILL` fallback / process-group kill), causing Windows `EBUSY` worktree lock races.
  - `buildSpawnCommand` wraps `.cmd`/`.bat` shims in `cmd.exe /c` without escaping cmd metacharacters (`&|<>^%`) in `systemPrompt` / `-c` args.
  - `cliStreamRuntime.ts:446` passes `BOT_FACTORY_TOKEN` in CLI `-c mcp_servers.*.env=...` (`argv`-visible!). And `engine.ts:1920` falls back to `this.runtimeCfg.sessionToken` (operator master token!) if `agent.projectId` is `null`.
- **Timeout recovery & early-break leaks** (`acpSubprocessRuntime.ts:739-823, 1124, 1280`; `cliStreamRuntime.ts:544-552, 671-705`):
  - `acp_turn_timeout` leaves a possibly wedged ACP child alive and lacks turn-generation filtering in `handleInboundLine`, so late `session/update` chunks leak into the next turn; `finally` (`:808-821`) leaks `reqId` in `pendingClientRequests`; `"Allow Session"` (`:1124, 1280`) auto-approves the entire `kind` (e.g. all `"execute"` bash commands).
  - `cli_stream_timeout` (`cliStreamRuntime.ts:548`) doesn't clear `state.proc`; early consumer break out of `sendTurn` (`:671-705`) releases `turnMutex` without terminating/cancelling the active CLI turn; Codex `turn.completed` (`:1064`) returns before `proc.exited` releases worktree file locks.
- **Stream parsing edge cases** (`acpSubprocessRuntime.ts:1033-1107`; `cliStreamRuntime.ts:482-500, 821-863, 973-976`):
  - `acpSubprocessRuntime.ts:1068-1086` (`pumpStdout`) drops any final non-`\n`-terminated JSON line on EOF (no `decoder.decode()` / tail flush) and never releases `reader` lock; `pumpStderr` uses unbounded `appendFileSync`.
  - `cliStreamRuntime.ts:482-500` (Claude `proc.exited`) doesn't await `stdoutDone` (racing with `result` parsing); `assistant` event (`:842-861`) duplicates `thought` blocks and `in_progress` `tool_call`s already emitted by `content_block_start`/`delta`; Codex `agent_message` chunks (`:973-976`) concatenate without `\n\n`; `state.toolNamesById` never clears per turn.
